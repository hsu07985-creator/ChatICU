## 1. 資料放哪裡

絕對路徑：`/Users/chun/Workspace/ChatICU_2026_verf_0110_Yu/patient/`

目錄結構（每位病人一個資料夾，以病歷號 MRN 命名）：

```
patient/
├── 16312169/                          ← 病歷號
│   ├── latest.txt                     ← 內容為最新 snapshot 名稱（例：20260423_182449）
│   └── 20260423_182449/               ← snapshot 資料夾（命名：YYYYMMDD_HHMMSS）
│       ├── ALL_MERGED.json            ← 主要資料來源
│       ├── getIpd.json                ← 住院資料
│       ├── getPatient.json            ← 病患基本資料
│       ├── getAllMedicine.json        ← 用藥
│       ├── getAllOrder.json           ← 醫囑
│       ├── getLabResult.json          ← 檢驗
│       ├── getSurgery.json            ← 手術
│       ├── getAIResult.json           ← ECG AI 判讀
│       ├── urls_all.txt
│       └── ExtraFactories/            ← 跨院區補充資料
│           ├── Factory_F/
│           ├── Factory_G/
│           ├── Factory_H/
│           └── Factory_Q/
├── 16592013/
│   └── ...
```

### 更新 `latest.txt`
放新資料後，**務必**把 `{MRN}/latest.txt` 改成新的 snapshot 資料夾名稱，例如：

```bash
echo "20260424_090000" > patient/16312169/latest.txt
```

`snapshot_resolver.py` 先讀 `latest.txt`，找不到才 fallback 去挑字典序最大的子目錄。

## 2. 正確的上傳流程（手動）

### Step 1 — 檢查目標資料庫

```bash
grep DATABASE_URL backend/.env.his-sync | sed -E 's#://[^:]+:[^@]+@#://***:***@#'
```

預期：`postgresql+asyncpg://***:***@aws-1-ap-southeast-2.pooler.supabase.com:6543/postgres`

如果不是，先修 `backend/.env.his-sync` 再繼續。

### Step 2 — Dry-run 預覽（安全，不寫 DB）

```bash
cd backend
python3 scripts/sync_his_snapshots.py --dry-run
```

看 summary：

| action | 意義 |
|--------|------|
| `new` | 病人首次進 DB |
| `changed` | 內容 hash 有變，會 sync |
| `timestamp-only` | 只有 snapshot_id 改了，內容沒變 → 跳過 |
| `unchanged` | 完全沒變 → 跳過 |
| `forced` | 你下了 `--force` 強制重跑 |

只有 `new / changed / forced` 會真的寫 DB。

### Step 3 — 單一病人試跑（可選但建議）

```bash
python3 scripts/sync_his_snapshots.py -p 16312169
```

看到類似輸出表示成功：

```
16312169
  action        : changed
  snapshot_id   : 20260423_182449
  patient_id    : pat_ed7bc912
  synced        : med_upserted=322 med_added=25 med_deleted=0 ...
```

### Step 4 — 全量同步

```bash
python3 scripts/sync_his_snapshots_serial.py
```

寫入模式固定使用 serial script，避免 Supabase transaction-mode pooler 在並行 task 下
出現回報成功但資料未落盤。`sync_his_snapshots.py` 只保留 `--dry-run` 預覽功能。

成功示意：

```
--- Summary ---
  forced=0, new=10, changed=5, timestamp-only=0, unchanged=0, synced=15
  errors=0
```

### Step 5 — 驗證

```bash
# 1) 後端健康
curl -s https://chaticu-production-8060.up.railway.app/health

# 2) 開前端，硬重整
open "https://chat-icu.vercel.app/patients"
# 在瀏覽器按 Cmd+Shift+R 清掉舊 cache
```

確認：
- [ ] 患者列表出現新病人
- [ ] 點進病人 → Medications tab 有藥
- [ ] Labs tab 有檢驗值
- [ ] Pharmacy → Duplicates 有重複用藥標記（會自動 refresh）

觸發。細節見 `docs/his-sync-schedule-and-manual-trigger.md`。

|------|------|
| `--dry-run` | 只預覽、不寫 DB |

## 5. Troubleshooting

### Q1. `action` 全部是 `unchanged`，但我明明有放新資料
- 檢查 `{MRN}/latest.txt` 內容是否指到新的 snapshot 資料夾名
- 確認新資料夾下真的有 `ALL_MERGED.json`（snapshot_resolver 會用它算 hash）
- 還是不行，用 `--force` 強制一次

### Q2. `action` 是 `error`，訊息說找不到某個欄位
- 先比對 `backend/app/fhir/his_lab_mapping.py` 是否有對應 LAB_CODE
- `ALL_MERGED.json` 結構可能變了 → 看 `backend/app/fhir/his_converter.py`

### Q3. DB 寫入報 `asyncpg` 錯誤
- 確認 `backend/.env.his-sync` 的 `DATABASE_URL` 用 `postgresql+asyncpg://` 前綴
- Supabase pooler port 是 `6543`（非 5432）

### Q4. 前端看不到新資料
- 先硬重整 `Cmd+Shift+R`（清 React Query cache）
- 確認 `.env.his-sync` 指的 DB 就是 Railway 後端讀的 DB（兩邊 `DATABASE_URL` 要一致）
- 看 Vercel 前端 network tab，請求有沒有透過 `/api/` proxy 轉發（不是直連 Railway）

### Q5. 同一位病人同步兩次，藥物會重複嗎？
- 不會。`import_his_patients` / `snapshot_sync` 都是**幂等 upsert**，靠 `patient_id` + natural key 避免重複
- 藥物會 `med_upserted`（更新）或 `med_added`（新增），不會重複 insert

### Q6. 可以刪掉舊 snapshot 資料夾嗎？
- 可以，系統只看 `latest.txt` 指到的資料夾
- 不過保留舊 snapshot 方便回溯與比對 hash 變動

## 7. HIS 無法提供的欄位（非 sync bug）

下列欄位 HIS API 沒有，sync 後仍會是空值，需要其他資料源或手動輸入：

- `bed_number` / `unit` — 待整合 GetIpd API
- `height` / `weight` / `BMI` — 要護理系統或手動
- `allergies` 明細 — 只有 `Smartbed.sbDisease.FOOD_ALLERGY` 有結構值時自動匯入；無值時保留人工輸入
- `is_isolated` / `campus` — HIS 無
- 生命徵象（Vital Signs）、呼吸器參數（Ventilator Settings）、Clinical Scores — HIS 無
